## Entry 1:
#### Corresponding log file: fuzzer-aug-19
Here, the model wanted to do two things that didn't make sense to me. First, it wanted to make its own linked list implementation as the reference model, which defeats the entire point of having an externally validated reference. I ended up telling it to go with an intrusive TALIQ sys/queue.h list as it is doubly linked, meaning the fuzzer's removal and random access will be faster compared to the SLIST alternative. Additionally, the only dependency is a libc header. Secondly, the model carried `g_failures` over from the table test cases. However, for the case of our fuzzer, we want to exit after a single failure instead of flooding the output with hundreds of later cases. The model also incorrectly assumed that this was because I wanted to avoid continuing on an invalidated model, stating that the test is dependent on previous iterations. This does not make sense as the failure should be an issue with unwind or allocation code after our fault injection, which happens only once per tree version anyway. I did not correct the model on this as it was functionally the same and did not want to waste input tokens.

## Entry 2:
#### Corresponding log file: aug-19-adversarial
This was an adversarial review that found four results. The most notable of which was the use of a seed argument in the main function of the fuzzer. The model discovered that A) this field existed and B) that it was always being overwritten by the DEFAULT_SEED. It wanted to make sure that the seed passed was used but I decided that, since there is no such usage of seeds in the MakeFile, that we will just always use the DEFAULT_SEED that is hardcoded in to the file. This reduces functionality but keeps the program simpler and better scoped. Therefore, it is worth the tradeoff.
